# Лабораторная №3: демонстрация REST и Postman

## Подготовка

1. Запустите проект командой `npm run dev` из корня проекта.
2. Убедитесь, что серверный `.env` содержит активированный `OMDB_API_KEY`.
3. В Postman выберите **Import** и импортируйте `MovieHub.postman_collection.json` и `Local.postman_environment.json` из этой папки.
4. Выберите окружение **MovieHub local**. Переменная `baseUrl` равна `http://127.0.0.1:3000`.
5. Для основной папки **MovieHub** ключ в Postman не нужен: запросы идут к нашему Express-серверу, который обращается к OMDb.

## Что показать преподавателю

1. Откройте запрос **01 — Сервер доступен**, нажмите **Send**. Покажите HTTP `200` и JSON `ok: true`.
2. Выполните **02 — Поиск Interstellar**. В **Params** покажите параметры `query` и `page`, в ответе — массив `movies`, `totalResults`, `totalPages`.
3. Откройте **03 — Фильтр по году** и покажите `year=2014`.
4. Выполните **04 — Подробности фильма**. IMDb ID автоматически сохраняется тестовым скриптом поискового запроса в переменную коллекции `movieId`. Покажите поля `plot`, `director`, `actors`, `rating`.
5. Выполните **05 — Вторая страница Batman**, сравните результаты с первой страницей.
6. Выполните **06 — Ничего не найдено**. Это корректный HTTP `200` с пустым массивом, а не поломка сервера.
7. Выполните **07** и **08**: неверные параметры дают `400`. Запрос **09** к отсутствующему фильму даёт `404`.
8. В **Scripts → Post-response** покажите проверки `pm.test` и `pm.expect`, затем результат во вкладке **Test Results**.
9. Запустите папку **MovieHub** через **Run** / Collection Runner. Один последовательный прогон содержит 9 запросов; все тесты должны пройти при доступном OMDb и активном ключе.
10. Откройте сайт `/movies.html`, найдите фильм и откройте карточку — интерфейс использует те же REST-маршруты.

## Прямые запросы OMDb (необязательно)

Папка **OMDb direct (optional)** содержит два HTTPS-запроса непосредственно к OMDb. Для них вручную укажите `omdbApiKey` в локальном значении окружения или замените ссылку на секрет Postman Vault. Не синхронизируйте и не экспортируйте заполненный ключ, не показывайте его в скриншотах. Не запускайте эту папку, пока переменная пуста.

Параметры внешнего API отличаются от нашего: OMDb использует `s` для поиска, `i` для IMDb ID, `y` для года и `plot=full` для полного описания. OMDb может вернуть HTTP `200` с `Response: "False"`; сервер MovieHub проверяет и HTTP-статус, и это поле, а затем возвращает понятную ошибку.

## Краткое объяснение REST

- Клиент обращается к ресурсам по URL: `/api/movies` — коллекция, `/api/movies/:id` — конкретный фильм.
- `GET` читает данные и не создаёт аккаунты или записи в базе. Поиск не требует авторизации.
- Фильтры и страницы передаются в query-параметрах. Ответ передаётся как JSON.
- Каждый запрос содержит необходимые параметры; сервер не хранит текущий поисковый запрос пользователя.
- `400` — неверный запрос; `404` — фильм отсутствует; `429` — локальное ограничение частоты; `502` — ошибка внешнего API; `503` — поиск не настроен или исчерпана квота; `504` — таймаут.
- Браузер → Express → OMDb → Express → браузер. Ключ остаётся на сервере.

## Автоматический прогон без GUI

В работающем проекте можно выполнить ту же коллекцию через Newman — CLI для коллекций Postman:

```bash
npm exec --yes --package=newman -- newman run postman/MovieHub.postman_collection.json --folder MovieHub
```

Этот прогон использует реальные ответы OMDb и расходует квоту при отсутствии записи в кэше. Изолированные тесты `npm test` используют поддельные ответы и квоту не расходуют.
